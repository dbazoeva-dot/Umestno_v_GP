## 3. Архитектурные решения

- **scheme-first верен**; первичен **DesignIntent** (красиво+удобно+реализуемо), не cells/assigned/SKU сами по себе.
- **Два слоя зоны:** `need` (правда, считается от вещи, по ней меряем дыры рынка — суверенен) и **косметика** (`assigned − need`, раздув D04b — договороспособный бюджет). Матчер целится в `assigned`; `need` пишем как сигнал.
- **Маховик:** строим от потребности → доставляем с рынка сейчас (бутстрап) → копим корпус `assigned_zones` + компромиссы → свои органайзеры через ~полгода.
- **Зона провизорна до подбора** (`footprint = real_cell × count`, а `real_cell` известен только после матча) → нужен **диалог движок↔матчер**, не односторонний конвейер.
- **НО глобальный match-and-place re-layouter не строим** — он (а) подчиняет дизайн рынку, (б) топит сигнал дыр. Вместо него: **суверенная need-схема + per-zone реализатор** (тайлим фикс-зону комбинацией товаров, footprint-locked) + **честные дыры** (пишем против need) + только **логируемые микро-нуджи**. Чужой категорией freed-место не заполняем (бренд «категории не смешиваются»).
- **Underfill — это бюджет**, не «молчание»: освободившееся место реклеймим/перетекаем; пишем полный дельта-вектор (over/under по обоим осям, против need и против design).
- **Confidence-лестница** (exact/compatible/acceptable/workaround/no_reliable) — пользовательская честность; технический `match_status` переименовать (exact→primary_match). *(не реализовано)*
- **Поворот:** вещь можно хранить перпендикулярно → для cells ячейка матчится в любой ориентации (сделано). Для slots поворот направленный.
- **modular** = признак «красиво комбинируется» (2/4 органайзера в зону) + позволяет докупать наборы (capacity нескольких наборов). *(ПАУЗА — не реализовано)*

## 4. Каталог / источник правды

- **Источник правды каталога — БД (prod), через SQL/DBeaver.** xlsx в репо (`v0106`) — старый разовый seed.
- **Loader `loadSkuToPostgres` (xlsx→DB) «на пенсии»:** он делает `ON CONFLICT DO UPDATE` (xlsx побеждает). Повторный запуск со старым xlsx **затрёт ручные правки** строк, которые есть в файле (соты вернулись бы в dividers), новые строки (055+) уцелеют. **Не запускать со старым файлом.**
- Прод-каталог **ушёл вперёд** репо-xlsx (в проде есть 055+, в xlsx максимум 054).
- У агента (этой среды) **нет доступа к прод-БД** (сеть закрыта + нет пароля). Для тестов на реальных данных нужен **дамп `sku`** (`\copy ... TO csv` на VPS).
- Если снова использовать xlsx как инструмент: сначала **DB→xlsx экспорт**, потом правка, потом заливка (иначе старый файл затрёт прод). Можно сделать `dumpSkuToXlsx`.

## 5. Разделители — два класса

- **Type A — модульные ячейки** (соты, кубики 7×7): фикс ячейка + N штук + произвольная раскладка → **это adjustable cells, УЖЕ работает**. Просто заводить в каталог. (Ozon-кубик — сюда.)
- **Type B — настоящие планки** (перегородки вдоль края, ячейка эмёрджентна) → **отдельная механика** «can-construct» (черновик в SPEC). **Отложено** до in-stock примера (единственный, Арникс, OOS).

## 6. Качество данных каталога (→ парсер / quality-flags)

Найденные дефекты (симптомы ручного ведения):
- хвостовой пробел в имени картинки (UM-SKU-053) — пофикшено;
- UM-SKU-030 — картинки нет (нужно залить);
- дубль `sku_id` UM-SKU-016 (два разных товара);
- название содержит размер/количество (теперь чистим на рендере);
- цвет в названии vs фото (LaDom «серый» vs белое фото);
- размеры узких-глубоких коробов — это НЕ баг (14×24 = узкий-глубокий верно).

## 7. Парсер каталога (нужен, не построен)

- БД уже спроектирована под него (`price_kop`=«снимок парсера», `availability_status`, `*_log`, `is_active`).
- Лёгкая часть (сбор полей + свежесть наличия/цены) — недели; затык — **доступ** (антибот → официальные API/партнёрские фиды).
- Тяжёлая часть — **извлечение геометрии** (division/cell/cols — почти никогда нет в карточке) → vision-LLM + ручная модерация спорного. Качество этого = фундамент точности матчера.

## 8. Открытые задачи

**Движок:**
- `modular` — несколько наборов в зону (ПАУЗА; нужен, чтобы новый кубик 6-ячеек закрывал носки/трусы >6).
- **zone-negotiation / глобальный ребаланс** (ужать underfill → вырастить overfill в пределах косметики) — крупное, отложено; без него соты-medium и 1-см промахи не доезжают.
- Type B dividers (can-construct) — ждёт in-stock примера.
- as-placed размеры в выдаче (опционально, убирает расхождение порядка размеров).

**Данные / каталог (прод, её):**
- UM-SKU-030 — залить картинку.
- (опц.) `dumpSkuToXlsx` для безопасного round-trip.
- прислать дамп `sku` — чтобы тесты шли на реальном каталоге.

**Из memo аналитика (приняты как рамка, не реализованы):**
- `recommendation_confidence` + copy; `sku_match_log` / `near_match` (Design Demand Ledger); quality-flags (no_bottom, weak_walls, unclear_cell_size, …); VisualZone (показывать сетку/слоты, не плоский прямоугольник).
